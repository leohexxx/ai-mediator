## 产品目标（一句话）

在 AI 调解员微信小程序现有单人上传 + OCR + AI 分析 + 追问能力基础上，完善追问环节隐私安全感、调整字数限制文案为建议性质、增强上传后背景信息补充能力、重构双人模式流程为辩论式补充分析。

## 1. 用户故事

### 需求 1：追问环节安全提示

| ID | 用户故事 |
|----|---------|
| US-01 | 作为**担心隐私的用户**，我在**追问 AI 调解员时**，希望**每次 AI 回复前都能看到隐私安全保障提示**，这样我能放心地说出真实想法而不用担心信息泄露 |

### 需求 2：字数限制文案更正（建议而非强制）

| ID | 用户故事 |
|----|---------|
| US-02 | 作为**上传了大量聊天记录的用户**，我希望**系统将字数限制明确表述为"建议"而非"强制"**，这样我能自由选择是否使用压缩版，而不会误以为必须压缩 |

### 需求 3：上传后补充背景信息/问题

| ID | 用户故事 |
|----|---------|
| US-03 | 作为**正在上传聊天记录的用户**，我希望**在备注区能用更详细、更有引导性的文案来补充背景信息**，并且**能输入更多内容**，这样 AI 能更准确地理解我的诉求和问题 |
| US-04 | 作为**产品运营**，我希望**用户补充的备注信息能完整传递到 AI 分析上下文中**，这样分析结果能融合用户的背景说明，提升分析质量 |

### 需求 4：双人模式改造

| ID | 用户故事 |
|----|---------|
| US-05 | 作为**甲方（案例发起方）**，我希望**不必等待乙方加入就能先上传证据并触发分析**，这样我不浪费等待时间（修复当前卡死 bug） |
| US-06 | 作为**乙方（受邀方）**，我希望**在甲方已有分析结果的基础上补充我的聊天记录**，然后触发**辩论式重新分析**，这样双方各自的立场都能被 AI 客观对比 |
| US-07 | 作为**使用 AI 调解员的用户**，我希望**调解方向偏积极正面但保持客观**，追问风格**避免"可能""也许"等模棱两可用词**，这样我能得到更清晰、更有建设性的指引 |

## 5. 数据流说明（需求 3：备注 → 分析上下文）

```
upload.js
  │ 用户填写 note
  │
  ▼
uploadEvidence 云函数
  │ 证据写入 evidence 集合:
  │ { caseId, party, rawText, note: "用户填写的备注", ... }
  │
  ▼
analyzeCase 云函数
  │ buildPartiesAndContext():
  │   1. 读取 caseData
  │   2. 读取该 case 最新 evidence 记录
  │   3. 提取 evidence.note 内容
  │   4. 追加到 caseContext 字符串
  │      → "用户补充说明: {note 内容}"
  │
  ▼
LLM 分析 prompt
  │ caseContext 中包含了用户的备注信息
  │ LLM 在分析时会引用用户补充的背景/问题
  │
  ▼
分析报告
  │ 结论中体现用户补充的背景信息
```

## 6. 双人辩论模式状态机

```
                      ┌──────────────────────┐
                      │  甲方创建双人案例      │
                      │  status: waiting_b    │
                      └──────────┬───────────┘
                                 │ 甲方先上传证据
                                 ▼
                      ┌──────────────────────┐
                      │  甲方上传证据 + 触发分析 │
                      │  status: analyzing     │
                      └──────────┬───────────┘
                                 │ 分析完成
                                 ▼
                      ┌──────────────────────┐
                      │  甲方分析完成          │ ◄──── 乙方加入后可查看
                      │  status: dual_a_submitted │
                      │  dualState: a_done     │
                      └──────────┬───────────┘
                                 │ 乙方补充证据
                                 ▼
                      ┌──────────────────────┐
                      │  乙方上传证据 + 触发    │
                      │  辩论式重新分析         │
                      │  status: analyzing     │
                      │  dualState: b_debating│
                      └──────────┬───────────┘
                                 │ 重新分析完成
                                 ▼
                      ┌──────────────────────┐
                      │  双方对比分析完成       │
                      │  status: dual_b_submitted  │
                      │  dualState: both_done  │
                      │  报告区分甲乙双方陈述    │
                      └──────────────────────┘
```

**关键变化**（对比当前流程）：
- **当前**：双人模式必须双方都提交后才触发分析 → **卡死 bug**（乙方未加入则永远无法分析）
- **改为**：甲方可先上传先分析（`dual_a_submitted`），乙方后可补充后重新分析（`dual_b_submitted`）
- 乙方补充证据后的分析为**辩论模式**，prompt 中明确标记，LLM 需对比双方证据做判断

## 7. 附录：关键 Prompt 变更草案

### 7.1 `chatPrompt.js` — 追加安全提示

在 `buildChatSystemPrompt` 返回的 prompt 末尾追加：

```
## 🔒 隐私安全保障

每次回答前，请在开头加上以下安全提示（作为回答的第一段）：

"🔒 全程匿名，安全无忧：本分析全程匿名处理，您的聊天记录和个人信息不会被存储或泄露。分析完成后数据可随时删除。请放心沟通。"

注意：语气要温暖自然，不要过于官方生硬。如果用户已经在同一轮对话中看到过此提示，可以改为简短的"🔒 您的隐私全程受保护，放心沟通～"
```

### 7.2 `analysisPrompt.js` — 调解方向调整

在 `buildStrategyUserPrompt` 的说明段中添加：

```
## 调解方向要求
- 调解建议应偏向积极正面的方向，促进双方理解和关系修复
- 但不是盲目积极，仍需保持客观公正
- 避免单纯指责某一方，而是提供建设性的改进方向
```

### 7.3 `chatPrompt.js` — 追问风格调整

在 `buildChatSystemPrompt` 的"回答要求"中添加：

```
- **措辞明确**：避免使用"可能""或许""也许"等模棱两可的词汇
- **积极建设**：回答偏积极正面方向，但保持客观，不盲目乐观
- **给出明确判断**：基于分析证据给出清晰的结论，而非模糊表述
```

### 7.4 辩论模式 prompt 注入

在 `buildPartiesAndContext` 中，当检测到辩论模式时：

```
## 双人辩论模式说明
本案例已由甲方先提供证据完成初步分析，现由乙方补充己方视角的聊天记录。
请进行对比分析：
1. 分别分析甲方和乙方的陈述与证据
2. 标注双方证据的一致点和矛盾点
3. 在"甲方陈述"和"乙方陈述"两个维度分别给出判断
4. 最后给出综合的客观判断
```

## 8. 待确认问题

| # | 问题 | 影响范围 | 建议/决策 |
|---|------|---------|----------|

| **Q5** | 辩论模式重新分析是否保留甲方之前提交的性格信息？ | P1-03 | 建议保留。性格信息在首次分析时已录入，辩论分析应基于已有性格数据 + 双方证据做判断 |

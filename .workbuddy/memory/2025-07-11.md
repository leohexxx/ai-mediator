## 第三轮 Bug 修复（深度审计后）

### 新发现的 Bug（共 6 个）

#### CRITICAL（功能完全不可用）
1. **聊天 SSE 解析错误**: api.ts sendMessage 函数 `fullContent += data` 直接拼接原始 SSE 字符串, 未 JSON.parse。服务端发送 `data: ${JSON.stringify(chunk)}`, 客户端应解析后拼接。导致聊天追问功能输出的文字全部带引号, 如 `"你""好"` 而非 `你好`。修复: JSON.parse 后判断 typeof string 拼接, 检测 error 对象抛出异常。
2. **聊天错误未处理**: 服务端 chat 端点出错时发送 `{error: "..."}`, 客户端不识别, 当聊天内容显示。修复: 在 SSE 解析中检测 parsed.error 并抛出。

#### MEDIUM
3. **分析失败错误信息丢失**: triggerAnalysis 的 `!res.ok` 直接 throw 'Analysis failed', 不读 response body。修复: 先 `res.json()` 读取 errBody.error, 拼入错误信息。额外增强: SSE 流中 step==='error' 也抛出实际错误。
4. **服务端启动不检查 API key**: 无 key 时静默启动, 用户第一次分析才发现。修复: server/index.ts 启动前检查三个 env 变量, 缺失时打印警告。
5. **服务端无 DELETE 端点**: 客户端删案例后服务端内存不清理。修复: cases.ts 新增 `DELETE /:id` 端点。
6. **README 过时**: 写着 Anthropic, 实际默认 DeepSeek。修复: 更新技术栈、环境变量说明（三提供商表格）、项目结构。

## 用户使用问题排查

### 问题: 用户打开 index.html 页面空白
- 原因: Vite 项目不能直接双击 index.html, 必须通过开发服务器运行
- 解决: 启动 `npm run dev` (前端 :3000) + `cd server && npm run dev` (后端 :3001)

### 问题: 分析功能报错 "The service was stopped"
- 原因: 旧的服务端进程 (PID 59968) 跑的是修复前的过期代码, tsx 启动后不会自动热更新源码
- API Key 确认: `.env` 中 `LLM_API_KEY=sk-23bd...` 配置正确, 直接调用 DeepSeek API 验证通过
- 解决: 杀掉旧进程 (PowerShell `Stop-Process -Id PID -Force`), 重启 `npx tsx src/index.ts`
- 验证: 重启后分析接口正常返回完整 JSON 分析结果

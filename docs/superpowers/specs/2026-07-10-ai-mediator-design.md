## 1. 产品概述

### 1.1 一句话定位
用户通过截图/录屏上传微信聊天记录，AI 自动识别人物关系、分析冲突对错、给出中肯建议，并支持双方补充证据进行交互式仲裁。

### 1.2 核心价值
- 中立第三方视角，避免情绪化判断
- 结构化分析让冲突双方看清问题本质
- 降低寻求情感建议的心理门槛（不用找人倾诉尴尬的事）

### 1.3 使用场景
- 个人自省：自己跟人吵架后，想客观理一理
- 朋友求助：帮朋友分析他们的聊天纠纷
- 双方对质：两人各自上传证据，AI 当"判官"
- 专业辅助：心理咨询师用来辅助分析来访者的人际冲突

### 2.2 技术选型

| 层 | 技术 | 理由 |
|---|---|---|
| 前端框架 | React 18 + TypeScript | 生态好，类型安全 |
| 构建工具 | Vite | 快速开发 |
| 样式 | Tailwind CSS | 快速出 UI |
| PWA | vite-plugin-pwa | 一键配置 |

## 3. 功能详细设计

### 3.1 上传模块

**输入方式**：
1. **截图上传**：支持拖拽/粘贴/文件选择，支持批量（多张截图自动排序）
2. **录屏上传**：支持 mp4/webm，后端抽取关键帧进行 OCR
3. **文字粘贴**：直接粘贴聊天文本（兜底方案）
4. **补充证据**：已有案例可追加新截图/录屏

**处理流程**：
```
截图 → 客户端 OCR 预处理 → 发送文本到后端
录屏 → 上传视频 → 后端 FFmpeg 抽帧 → 每帧 OCR → 去重拼接文本
文本 → 直接用于分析
```

### 3.2 AI 分析引擎

**Pipeline（5 步）**：

```
原始文本
  ↓
Step 1: 对话解析
  - 识别说话人（微信格式：昵称: 内容）
  - 提取时间戳
  - 识别消息类型（文字/语音转文字/表情包描述）
  ↓
Step 2: 语义理解
  - 情绪识别（每句话的情绪标签）
  - 上下文关联（回复关系）
  - 话题检测（在聊什么）
  ↓
Step 3: 人物画像
  - 识别对话中的所有人
  - 判断人物关系（情侣/朋友/同事/家人等）
  - 分析各自立场和诉求
  ↓
Step 4: 冲突分析
  - 定位关键冲突节点
  - 分析各方言行是否合理
  - 判断"对错"（附理由）
  ↓
Step 5: 生成报告
  - 摘要：一句话总结
  - 人物关系图
  - 冲突时间线
  - 逐条分析（关键对话 + 解读）
  - 对错判断（谁对谁错 + 依据）
  - 建议（双方各应该怎么做）
```

### 3.3 交互式追问

用户可以在报告页面对 AI 进行追问：
- "他说的这句话到底什么意思？"
- "如果我不那样回复会怎样？"
- "从女生的角度怎么看这件事？"

追问时带上完整聊天上下文，保持分析连贯性。

### 3.4 证据补充机制

- 任一用户（"原告"或"被告"）可以上传补充材料
- 补充后触发重新分析
- 新旧证据的差异点会被高亮显示
- 支持标记证据来源（谁上传的）

## 4. 数据流

### 4.1 主流程

```
用户操作             前端                   后端                  AI
   │                  │                     │                    │
   ├─上传截图─────────→│                     │                    │
   │                  ├─OCR预处理───────────→│                    │
   │                  │                     ├─文本格式化          │
   │                  │                     ├─调用LLM分析────────→│
   │                  │                     │←─分析结果───────────┤
   │                  │←─SSE流式返回报告─────│                    │
   │←─逐段展示报告─────│                     │                    │
   │                  │                     │                    │
   ├─追问问题─────────→│                     │                    │
   │                  ├─发送上下文+新问题────→│                    │
   │                  │                     ├─LLM追问────────────→│
   │                  │←─流式返回───────────│←────────────────────┤
   │←─展示回答─────────│                     │                    │
```

### 4.2 存储模型（MVP）

```
Case {
  id: string
  title: string
  createdAt: Date
  parties: Party[]        // 各方信息
  evidence: Evidence[]    // 证据列表
  rawText: string         // 提取后的完整文本
  analysis: Analysis      // 最新分析结果
  chatHistory: Message[]  // 追问历史
}

Evidence {
  id: string
  type: 'screenshot' | 'screen_recording' | 'text' | 'file'
  source: 'party_a' | 'party_b' | 'self'
  fileUrl: string
  extractedText: string
  uploadedAt: Date
}

Analysis {
  summary: string
  characters: Character[]
  timeline: TimelineEvent[]
  conflicts: Conflict[]
  verdict: Verdict
  advice: Advice
}

Verdict {
  winner: string          // 谁更有理
  scoreA: number          // A的合理度评分
  scoreB: number
  reasoning: string[]
}
```

## 5. API 设计

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/cases` | POST | 创建新案例 |
| `/api/cases/:id` | GET | 获取案例详情 |
| `/api/cases/:id/evidence` | POST | 上传证据(截图/录屏) |
| `/api/cases/:id/analyze` | POST | 触发分析 |
| `/api/cases/:id/chat` | POST | 追问（SSE 流式返回） |
| `/api/cases/:id/report` | GET | 获取分析报告 |
| `/api/ocr` | POST | OCR 识别（客户端预处理后用） |

## 6. UI 设计要点

### 6.1 关键页面
1. **首页** — 新建案例入口 + 历史案例列表
2. **上传页** — 截图/录屏上传区 + 补充说明输入
3. **分析中** — 进度动画 + 实时日志展示
4. **报告页** — 结构化分析报告
5. **对质模式** — 双栏布局，双方证据并排

### 6.2 设计风格
- 色调：深蓝 + 金色点缀（法庭/仲裁的正式感 + AI 科技感）
- 风格：现代简约，卡片式布局
- 移动优先：触控友好的大按钮、滑动操作

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 微信没有公开 API | 数据获取困难 | 截图/录屏绕过，OCR 提取 |
| OCR 准确率不足 | 分析质量差 | 双重 OCR（客户端+云端），人工校对环节 |
| 隐私合规 | 用户不信任 | 本地 OCR 优先，数据不落服务器，隐私声明 |
| AI 分析不够准确 | 用户不满意 | 多模型对比，用户纠错反馈循环 |
| 视频文件过大 | 上传慢 | 客户端压缩 + 分片上传 + 关键帧提取 |
| iOS 截长图不便 | 用户体验差 | 录屏作为主要方式 + 引导用户多张截图 |

# V3 架构：规则优先的证据分析

版本：`0.3.2`
日期：2026-08-19

## 目标

V3 将确定性问题从 DeepSeek 中移出。模型只处理上下文歧义、多种可能解释和沟通建议，降低延迟、费用和幻觉风险。

```text
截图/文本
  -> OCR、长图切片、去重、人工校对
  -> 证据版本快照
  -> 规则引擎：身份、统计、事实、质量、脱敏、安全分流
       -> 证据不足/紧急安全：确定性报告，不调用 LLM
       -> 可分析：标签检索知识库 + 必要证据片段
  -> DeepSeek Flash/Pro
  -> JSON结构、证据引用、置信度服务端校验
  -> 版本化报告
```

## 决策边界

### 后端直接判断

- 案件参与方、上传方、发起方和证据版本。
- 消息数量、字符数、说话人比例、消息类型、时间覆盖和可计算的回复间隔。
- 金额、日期、明确承诺、确认、道歉和拒绝等规则事实。
- OCR 平均置信度、低置信度段落、单双方证据覆盖。
- 单方证据置信度上限、低 OCR 与说话人未知的置信度限制。
- 暴力、自伤、威胁、诈骗和未成年人关键词的安全分流。

当事人可自愿填写 MBTI、星座和属性。分析启动时由用户选择视角：默认“只按证据分析”不传递这类资料；“证据 + 沟通画像”才将其作为沟通偏好参考传入模型，并生成独立的沟通画像区。服务端仅接受预定义枚举值，资料只可调整建议的措辞、节奏与渠道；不得用于事实、责任、证据充分度或置信度判断。视角和资料均属于分析缓存键的一部分，修改后会生成新的建议版本。

规则提取结果代表“在原文中找到了某种表达”，不等于事实已经被证明，也不用于自动认定法律责任。

### DeepSeek 负责

- 省略、反话、指代和跨消息上下文。
- 双方对同一事实的不同解释及不确定性。
- 争议聚类、情绪变化线索和非对抗沟通建议。
- 深度模式中的多个竞争性解释。

模型不得覆盖服务端身份、版本、质量和风险数据，不得引用不存在的消息 ID。

## 知识库

首版知识库位于 `ai-mediator-backend/cloudrun/services/knowledgeBase.js`，版本为 `2026.08-v1`。内容包括：

- 事实—感受—需要—请求表达框架。
- 金额、日期和承诺的核对方法。
- 单方证据边界。
- 人身安全、诈骗和未成年场景的优先处置原则。

当前语料规模小，使用标签检索比向量数据库更可控、延迟更低。知识条目进入报告时保留 `id` 和 `version`。当人工审核语料达到数百个切片、标签检索召回不足时，再评估独立向量检索；用户聊天证据不得进入跨案件共享知识库。

## 报告契约

V3 服务端分析记录使用 `schemaVersion: v5` 和 `promptVersion: v3.0.0`。核心新增字段：

- `reportSections.commonGround`
- `reportSections.disputedIssues`
- `reportSections.missingEvidence`
- `reportSections.nextActions`
- `extractedFacts`
- `evidenceFeatures`
- `evidenceQuality`
- `safetySignals`
- `knowledgeReferences`
- `modelUsage`、`modelAttempts`、`cacheHit`、`llmSkippedReason`

旧的 winner/score 字段仅保留数据兼容，不再作为 V3 小程序核心界面。

## 性能策略

- 快速模式最多选择约 52 条关键证据片段，深度模式约 100 条；不再发送全部 OCR 原文。
- 证据不足和紧急安全分流跳过 LLM。
- 缓存键包含案件、证据版本、模式、模型和提示词版本；相同输入可复用完成报告。
- Flash 用于快速模式，Pro 用于深度模式；Pro 遇到可重试故障后降级至 Flash。
- 仅对超时、429、5xx 和临时网络错误有限重试；4xx 参数/权限错误不重试。
- 记录预处理、排队、模型、解析、总耗时、Token、缓存命中和结构化运行指标。

## 安全和隐私

- 模型输入不包含 OpenID，自动替换手机号、身份证号、长账号、邮箱和 URL。
- 数据库业务集合维持客户端不可直接读写，服务端再次校验案件参与方。
- 安全关键词只触发保守分流，不构成医学、法律或违法定性。
- V3 未实现覆盖云存储和全部派生记录的一键删除，因此前端隐私文案不作此承诺。

## 风险

- 正则事实可能漏检口语和方言，也可能把引用他人的话识别为本人承诺；报告必须保留原消息 ID。
- 标签知识库依赖人工维护，应有来源、审核和版本流程后再扩大。
- 缓存会固化同一提示词版本的结果；修改提示词必须更新 `PROMPT_VERSION`。
- 高风险关键词可能误触发，宁可提供保守安全提示，不自动给用户贴标签。

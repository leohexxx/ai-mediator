## 1. 战略诊断：为什么当前架构不适合快速获客

### 1.1 现有架构的核心矛盾

```
用户打开小程序 → 创建案例 → [必须等待乙方加入] → 双方上传 → 等待分析 → 查看结果
                         ↑
                    最高流失点：找不到人加入
```

**数据推演（基于行业平均转化率）**：

```
100 人打开小程序
  → 70 人创建案例（创建门槛低）
  → 20 人成功邀请到对方（邀请是最大漏点）
  → 18 人双方都提交
  → 17 人看到分析结果
  → ~3 人分享出去

获客效率：每 100 用户仅带来 ~3 次分享，无法自增长
```

### 1.2 四个致命问题

| # | 问题 | 影响 |
|---|------|------|
| 1 | **双人协作是获客杀手**：用户来了必须找到对方才能体验核心价值 | 转化漏斗断崖，day1 留存 < 10% |
| 2 | **没有单人模式降级**：乙方不加入 = 产品无价值，用户直接流失 | 无法形成使用习惯 |
| 3 | **分享价值不够强**：分享的是"邀请对方来调解"，不是"你看 AI 说谁对" | 分享动机弱，传播率低 |
| 4 | **分析结果缺乏传播性**：长报告无法作为社交货币在聊天/朋友圈传播 | 错失微信生态最大优势 |

## 2. 核心策略：从"双人调解室"到"单人仲裁+社交裂变"

### 2.1 战略调整

```
调整前：双人协作调解室（重操作，轻传播）
  ┌──────┐    ┌──────┐
  │ 甲方  │ ←→ │ 乙方  │   双方必须都参与
  └──┬───┘    └──┬───┘
     └────┬─────┘
          ↓
      AI 分析
          ↓
      报告（私密）

调整后：单人仲裁 + 结果即内容 + 分享裂变（轻操作，重传播）
  用户 ───→ 上传聊天 ───→ AI 分析 ───→ 报告卡片 ───→ 分享到朋友圈/群
                                          ↓
                                    "想知道对方怎么说？
                                     邀请TA也来分析 →"
                                          ↓
                                    双人模式（后续版本）
```

### 2.2 核心竞争力重塑

| 维度 | 旧定位 | 新定位 |
|------|--------|--------|
| **一句话** | "让双方各自上传证据，AI 匿名仲裁" | "上传聊天记录，AI 告诉你谁更有理" |
| **使用门槛** | 需要两个人 | **一个人就能用** |
| **核心价值** | 调解工具 | **娱乐+社交货币** |
| **传播载体** | 邀请链接 | **分析结果卡片（朋友圈/群聊）** |
| **增长引擎** | 工具型分享 | **内容型裂变** |

### 2.3 为什么这个策略适合微信生态

微信的核心优势是**社交关系链 + 群聊场景**。AI 调解员的天然优势是：

1. **聊天记录人人都有**：不需要额外创作内容
2. **争议分析天然有话题性**："AI 说谁对？"极具讨论价值
3. **群聊是天然分发场景**：朋友群、同学群、家庭群都是天然使用场景
4. **朋友圈分享有面子**："AI 说我更有理"是极佳的社交货币

## 3. 分阶段架构设计

### 3.1 三阶段路线图

```
Phase 1: 单人模式 MVP（第 1-2 周）
  ├── 微信登录
  ├── 上传聊天记录（文本/截图）
  ├── AI 单人分析
  ├── 报告页面（精简版）
  └── 分享卡片（核心增长引擎）
  
  → 目标：1 人即可完整体验 → 分享带来新用户

Phase 2: 分享裂变增强（第 3-4 周）  ← 此阶段开始获客
  ├── 多种分享卡片模板
  ├── 话题广场（公开案例）
  ├── 朋友圈分享图（Canvas 绘制）
  ├── "邀请对方也来分析" 引导
  └── 数据看板（分享率、转化率）
  
  → 目标：分享率 > 15%，裂变系数 K > 1.2

Phase 3: 双人协作模式（第 5-8 周）
  ├── 邀请机制（复用现有代码）
  ├── 双方独立上传
  ├── 交叉验证分析
  └── 隐私控制
  
  → 目标：双人模式作为高级功能，覆盖深度使用场景
```

**分享卡片变体（A/B 测试储备）**：

| 模板 | 风格 | 适用场景 | 预期 CTR |
|------|------|---------|---------|
| **裁决版** | 正式、权威 | 群聊分享 | 8-12% |
| **趣味版** | 轻松、段子感 | 朋友圈 | 15-20% |
| **悬念版** | 只显示分数不显示结论 | 私聊引导 | 20-25% |
| **对比版** | 两边观点并列 | 群聊引发讨论 | 18-22% |

### 4.3 小程序码追踪体系

```
分享卡片 → 小程序码（scene 参数编码）
  ├── scene=share_{caseId}        → 直接进入报告页查看
  ├── scene=invite_{inviteCode}   → 进入加入案例流程（Phase 3）
  └── scene=home                  → 首页（默认）

追踪维度：
  ├── 分享来源（群聊/朋友圈/私聊）
  ├── 卡片模板类型 → A/B 测试优化
  ├── 分享 → 打开转化率
  ├── 打开 → 创建案例转化率
  └── 创建 → 分享转化率（裂变闭环率）
```

### 4.4 裂变闭环的用户心理

```
触发：看到朋友的分享卡片 → "AI 说 XX 更有理？"
  ↓
好奇：我的聊天记录会是什么结果？
  ↓
行动：扫码进来 → 上传自己的聊天记录 → 得到结果
  ↓
满足：看到自己的分数 + 结论
  ↓
分享冲动：把有趣的结果分享给朋友/群
  ↓ (回到触发)
闭环完成
```

### 5.2 单人模式 analyzeCase 改造

```javascript
// analyzeCase/index.js 关键改动
exports.main = async function (event, context) {
  // ... 前置代码不变 ...

  // 【改动点】检查双方提交状态 → 允许单人分析
  var partyASubmitted = caseData.party_a && caseData.party_a.submitted;
  var partyBSubmitted = caseData.party_b && caseData.party_b.submitted;

  if (!partyASubmitted && !partyBSubmitted) {
    return { code: -1, data: null, message: '请先上传聊天记录' };
  }

  // 单人模式：仅用一方证据
  var isSingleParty = !partyBSubmitted;
  
  // ... 获取证据时判断 ...
  if (isSingleParty) {
    // 单人模式：confidence 自动降低 15-20%
    // 分析的 parties 参数仅包含甲方
    // onProgress 回调中标注"单人分析，置信度可能偏低"
  }

  // ... 后续逻辑不变，但分析完后的 confidence 字段加权 ...
  if (isSingleParty && analysis.coreConclusion) {
    analysis.coreConclusion.confidence = Math.max(
      0, 
      (analysis.coreConclusion.confidence || 75) - 15
    );
    analysis.coreConclusion.confidenceReasons = [
      '(单人视角分析，置信度已自动调低)',
      ...(analysis.coreConclusion.confidenceReasons || [])
    ];
  }
};
```

### 5.3 新增 shareCard 云函数

```javascript
// cloudfunctions/shareCard/index.js
// 在服务端用 Canvas 绘制分享卡片，避免小程序端 Canvas 兼容问题

var cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });

// 注意：云函数中不能使用 wx.canvas API
// 方案：使用 node-canvas 或纯 SVG 转图片
// 简化方案：返回结构化数据，小程序端用 Canvas 2D 绘制

exports.main = async function (event, context) {
  var { caseId, template } = event; // template: 'verdict' | 'fun' | 'suspense' | 'compare'
  
  // 1. 获取分析结果
  var db = cloud.database();
  var analysis = await db.collection('analyses')
    .where({ caseId })
    .orderBy('createdAt', 'desc')
    .limit(1)
    .get();
  
  if (!analysis.data.length) {
    return { code: -1, message: '分析结果不存在' };
  }
  
  var result = analysis.data[0];
  var core = result.coreConclusion;
  
  // 2. 生成带参小程序码
  var qrcodeResult = await cloud.openapi.wxacode.getUnlimited({
    scene: 'share_' + caseId,
    page: 'pages/report/report',
    width: 280,
  });
  
  // 3. 上传小程序码到云存储
  var qrcodeUpload = await cloud.uploadFile({
    cloudPath: 'share/qrcode_' + caseId + '.png',
    fileContent: qrcodeResult.buffer,
  });
  
  // 4. 返回卡片数据
  return {
    code: 0,
    data: {
      template: template || 'verdict',
      // 小程序端用这些数据 + Canvas 2D 绘制卡片
      cardData: {
        scoreA: core.scoreA,
        scoreB: core.scoreB,
        winner: core.overallWinner,
        verdict: core.oneLineVerdict,
        confidence: core.confidence,
        qrcodeFileID: qrcodeUpload.fileID,
      },
    },
    message: 'ok',
  };
};
```

## 6. 用户增长漏斗设计

### 6.1 三级转化漏斗

```
┌─────────────────────────────────────────────────────┐
│ 第一级：曝光 → 打开                                   │
│                                                     │
│  渠道：                                              │
│  ├── 微信群聊分享卡片（有机）                           │
│  ├── 朋友圈分享海报（有机）                             │
│  ├── 微信搜一搜（自然流量）                             │
│  └── 公众号文章嵌入（后续）                             │
│                                                     │
│  目标 CTR：群聊 12%+ / 朋友圈 8%+                      │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│ 第二级：打开 → 创建案例 → 分析完成                      │
│                                                     │
│  关键转化节点：                                       │
│  ├── 打开后 3 秒内传达"这是什么"（首页 Hero）            │
│  ├── 点击"开始分析"（0 门槛，不需要注册）                │
```

### 6.2 裂变系数估算

```
K = 曝光 × CTR × 转化率 × 分享率 × 平均分享次数

假设：
  每人平均 3 次分享
  每次分享触达 50 人（群聊平均）
  CTR = 10%
  转化率（打开→分析完成）= 40%
  分享率（分析完成→分享）= 25%

K = 50 × 0.10 × 0.40 × 0.25 × 3 = 1.5

结论：K > 1，具备自增长能力
```

## 8. 技术决策与风险

### 8.1 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **分享卡片生成** | 小程序端 Canvas 2D + 云函数生成小程序码 | 云函数不支持 wx.canvas，Canvas 2D 在小程序端已成熟 |
| **单人模式实现** | 扩展现有 analyzeCase，而非新建云函数 | 减少重复代码，统一维护 |
| **隐私处理** | Phase 1 单人模式默认"仅自己可见"，分享时去敏 | 先做安全，再开放 |
| **追问功能** | Phase 1 暂不上线 | 追问对服务器压力大（流式），且对获客 ROI 低 |
| **云开发配额** | 继续使用免费版 | 日活 < 1000 时免费版足够 |

### 8.2 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **微信审核不通过**（工具类目 vs 社交类目） | 中 | 高 | 注册"工具 > 信息查询"，避免社交功能描述 |
| **分享卡片在小程序端被拦截** | 低 | 中 | 使用官方 `onShareAppMessage` + Canvas 保存图片，不走非官方通道 |
| **单人分析置信度低导致用户不信任** | 中 | 中 | 报告中明确标注"单人视角"，引导邀请对方提升准确度 |
| **LLM API 按量付费成本超预期** | 中 | 中 | 设置每日调用上限 + 缓存相同输入结果 |
| **竞品快速跟进** | 低 | 高 | 用速度换时间窗口，2 周上线占先发优势 |

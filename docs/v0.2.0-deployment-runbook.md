# v0.2.0 部署与回滚手册

目标环境：`cloudbase-d4g5p82875fe1a5ce`。服务：`ai-mediator-backend`。容器端口：`9000`。

## 发布前门禁

1. 在独立测试环境执行 `npm ci && npm run test:all && npm run build`。
2. 运行旧数据迁移 dry-run：`npm run migrate:v0.2.0:dry-run --prefix ai-mediator-backend/cloudrun`，核对案例、旧证据与新增批次数量。
3. 确认以下密钥只存在于 CloudRun 环境变量，不在 Git、镜像层、日志或小程序包中：
   - `CLOUDBASE_APIKEY`
   - `LLM_API_KEYS`
   - `TENCENT_OCR_SECRET_ID`
   - `TENCENT_OCR_SECRET_KEY`
   - `NOTIFICATION_INTERNAL_TOKEN`（CloudRun 与 `sendAnalysisNotification` 云函数配置相同的随机值）
4. `CLOUDBASE_APIKEY` 是服务端 API Key。SDK 会优先使用它；数据库客户端规则不约束该身份，因此所有接口必须保留参与方鉴权。

## CloudRun 配置

- 访问类型：仅 `MINIAPP`，不得开放公网访问。
- 最小实例：`2`；最大实例：`10`。
- 每实例分析并发：`ANALYSIS_JOB_MAX_CONCURRENT=2`。
- OCR 并发：`OCR_MAX_CONCURRENT=4`。
- 健康检查：`GET /api/health`。
- 运行指标：`GET /api/health/metrics`，只返回聚合计数，不包含用户或案件标识。
- 其余推荐值见 `ai-mediator-backend/cloudrun/.env.example`。

## 数据库集合与索引

先创建集合，再应用 `database-rules/server-only.json`：

`cases`、`analyses`、`analysis_rate_limits`、`evidence`、`evidence_batches`、`invitations`、`users`、`share_cards`、`messages`、`conversation_messages`、`chat_jobs`、`ocr_jobs`。

`ocr_jobs` 是 V3.9 异步截图 OCR 的必需集合。可以在注入生产 CloudBase 凭据后执行：

```bash
npm run db:ensure-collections --prefix ai-mediator-backend/cloudrun
```

确认集合存在后，再对 `ocr_jobs` 应用 `database-rules/server-only.json`。不要让小程序直接读写该集合。

建议复合索引：

- `evidence_batches(caseId ASC, revision ASC)`
- `evidence_batches(caseId ASC, idempotencyKey ASC)`
- `analyses(caseId ASC, idempotencyKey ASC)`
- `analyses(status ASC, job.leaseUntil ASC)`
- `conversation_messages(caseId ASC, createdAt ASC)`
- `chat_jobs(caseId ASC, createdAt ASC)`

规则变更后必须用非参与者账号验证无法读取所有业务集合。

## 数据迁移

在数据库备份完成后才可写入：

```powershell
$env:MIGRATION_CONFIRM = 'v0.2.0'
node ai-mediator-backend/cloudrun/scripts/migrate-v020.js --apply
```

迁移是幂等的：旧 `evidence` 使用 `legacy_<evidenceId>` 写入 `evidence_batches`，无法确认的历史版本统一为 revision 1。旧集合暂不删除，用于回滚。

## 灰度与告警

先向测试环境发布脱敏样本，再灰度 10% 流量并观察 24 小时。建议告警：

- `analysis_queue_length > 20` 持续 5 分钟；
- 分析失败率或 OCR 失败率 `> 1%` 持续 10 分钟；
- 快速模式 P95 `> 45s`、深度模式 P95 `> 90s`；
- LLM token 或费用的小时增幅超过预算阈值；
- CloudRun 实例数达到 10 或 5xx 比例 `> 1%`。

## 回滚

1. 将小程序 `miniprogram/config/cloudrun.js` 的 `enabled` 临时设为 `false`，重新上传小程序体验版；旧云函数仍保留。
2. CloudRun 回滚到上一个可用版本；不要删除 `evidence_batches` 或旧 `evidence`。
3. 如需恢复旧追问读取，才临时应用旧版本 `messages` 规则；正常 v0.2.0 一律保持服务端只读写。
4. 未完成验收前不创建 `v0.2.0` Git 标签。

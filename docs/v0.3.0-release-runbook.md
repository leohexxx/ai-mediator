# V3 发布与回滚手册

V3 是原小程序 `wxf82c52d4800346a6` 的 `0.3.2` 更新，不创建新小程序、测试小程序或新 CloudBase 环境。

## 发布前门禁

1. 确认工作树无环境文件和真实密钥，运行 `git diff --check`。
2. 运行 `npm run test:all` 和 `npm run build`。
3. 检查 `project.config.json` 的 AppID 和 `miniprogramRoot` 未变化。
4. 确认 CloudRun 监听 `PORT=9000`，健康检查 `/api/health` 可用。
5. 确认 CloudRun 访问类型仍为 `MINIAPP`，最小实例 2、最大实例 10、单实例分析并发 2。
6. 确认已配置 CloudBase 环境 ID、服务端 API Key、DeepSeek Flash/Pro、腾讯 OCR 和通知令牌。
7. 正式客户端切换后，对业务集合应用 `database-rules/server-only.json`。

## 发布顺序

1. 备份当前 CloudRun 配置和最新正常部署编号。
2. 部署 `ai-mediator-backend/cloudrun`，不要改变服务名和访问类型。
3. 调用健康检查；使用脱敏样例验证：规则跳过 LLM、普通快速分析、深度降级、取消和缓存命中。
4. 用原项目目录导入微信开发者工具，确认 AppID 正确。
5. 上传版本号 `0.3.2`，体验版用双账号完成单人、双人、9+2 连续图片、OCR校对、并发启动和打断回归，并分别验证“只按证据分析”和“证据 + 沟通画像”不会复用同一报告。
6. 观察 CloudRun 日志中的 `operational_metrics`，确认解析失败率、重试率和总耗时无异常后再提交审核。

## 验收重点

- 明确金额、日期和单方状态来自 `extractedFacts/evidenceQuality`，不是模型自由生成。
- 手机号等敏感字段不出现在模型输入测试桩中。
- 证据不足时 `llmSkippedReason=insufficient` 且 Token 为 0。
- 紧急安全文本时 `llmSkippedReason=safety`，报告不输出输赢结论。
- 模型返回不存在的消息 ID 时，对应证据引用被删除。
- 相同证据版本、模式和提示词再次分析时可命中缓存。
- 小程序隐藏后停止轮询，重新显示后恢复。

## 回滚

1. CloudRun 流量切回上一个正常部署，不删除 V3 数据字段。
2. 微信公众平台回退至上一个已审核小程序版本。
3. 不回退数据库的证据版本字段；V2 读取会忽略新增 V3 字段。
4. 若问题来自知识条目或提示词，先更新版本号禁用缓存，再重新部署，不直接改写历史报告。

## 1. 产品定位与核心价值

### 一句话定位

**AI 调解员是一款基于聊天记录截图的争议分析工具——上传对话截图，AI 帮你拆解谁更有理、为什么、下一步该怎么做。**

### 与直接用 ChatGPT 的核心差异化

| 维度 | 直接用 ChatGPT | AI 调解员 |
|------|---------------|-----------|
| **输入方式** | 手动粘贴文字，需自行整理格式 | 截图直接上传，OCR 自动提取+解析说话人 |
| **输出结构** | 一段文字回答，信息平铺 | 分层递进报告：结论→证据→情绪→策略，核心结论第一屏可见 |
| **分析深度** | 泛泛而谈，无证据溯源 | 每条关键对话标注证据权重和偏向，判断有据可查 |
| **判断可信度** | 无法评估 | 标注置信度+原因（证据充分/信息缺失等） |
| **可操作性** | 建议笼统 | 分步调解策略（第一步做什么、预期效果、难度） |
| **追问上下文** | 每次重新解释背景 | 基于完整分析报告上下文追问，无需重复 |

### 为谁解决什么问题

**目标用户**：卷入微信/社交软件文字纠纷的普通人，想搞清楚"到底谁对谁错"但缺乏客观第三方视角。

**核心痛点**：
- 旁观者不清：身处争执中难以客观判断
- 证据散乱：聊天记录几百条，不知道哪些是关键
- 缺乏指导：知道有问题但不知道怎么解决
- 不想找真人：隐私顾虑，不想让朋友/家人知道

## 2. 用户画像

### 画像 A：情绪受害者小林

| 属性 | 描述 |
|------|------|
| **年龄** | 22-30 岁 |
| **职业** | 上班族 / 学生 |
| **场景** | 和伴侣/朋友发生微信争吵，对方说了一些伤害性的话，小林觉得自己被委屈了但说不清到底谁对 |
| **需求** | 想要一个客观的第三方视角，告诉他"你确实被冤枉了"或"其实你也有问题" |
| **行为** | 会截图保存聊天记录，习惯用手机处理一切 |
| **痛点** | 不敢找朋友评理怕丢面子，自己越想越气 |

| 属性 | 描述 |
|------|------|
| **年龄** | 30-45 岁 |
| **职业** | HR / 团队管理者 / 社区工作者 |
| **场景** | 下属/成员之间发生文字冲突，需要客观分析后介入调解 |
| **需求** | 需要结构化的分析报告，有证据支撑，方便用来做调解依据 |
| **行为** | 会收集双方截图，需要可操作的分步调解方案 |
| **痛点** | 手动翻聊天记录耗时，凭感觉调解容易偏颇 |

| 属性 | 描述 |
|------|------|
| **年龄** | 25-35 岁 |
| **职业** | 任意 |
| **场景** | 刚和人吵完架，冷静下来后想复盘自己的问题 |
| **需求** | 想看到自己的情绪变化轨迹，理解冲突升级的过程，学习沟通改进 |
| **行为** | 对"情绪曲线"和"调解策略"特别感兴趣 |
| **痛点** | 不知道冲突是怎么升级的，想避免下次重蹈覆辙 |

## 4. 需求池

### P0 — Must Have（必须完成）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|---------|
| P0-01 | **上传流程方案D** | 进入上传页即显示上传区，不强制先填表单。第一个上传默认标记为甲方，后续上传可选择乙方/自己。OCR 完成后自动从文本中提取说话人名字填充到甲乙方字段。关系类型后置为可选项。用户可随时修改所有字段。 | 1. 进入页面 ≤1s 看到上传区 2. 上传后 OCR 自动提取说话人 3. 甲乙方名字可编辑 4. 关系类型可选不选 |
| P0-02 | **Prompt 重构（CoT）** | 重写 LLM Prompt，使用思维链引导：先理解对话→识别关键证据→追踪情绪→综合判断→制定策略。输出分层 JSON 结构而非平铺。 | 1. Prompt 包含明确的分析步骤 2. 输出 JSON 符合新 schema 3. 结论有证据引用支撑 |
| P0-03 | **核心结论前置** | 报告第一屏显示：谁更有理 + 一句话原因 + 分数对比 + 建议行动 + 置信度。不滚动即可看到全部核心信息。 | 1. 首屏不滚动可见结论 2. 包含 winner/score/原因/行动/置信度 |
| P0-04 | **证据权重** | AI 标注 3-8 条关键对话，每条包含：原文、说话人、权重分(0-100)、偏向哪方、权重原因。 | 1. 每条证据有 weight + favors + weightReason 2. 可点击查看原文上下文 |
| P0-05 | **置信度标注** | AI 输出判断置信度(0-100) + 置信度原因（证据充分/信息缺失/双方各有道理等）。 | 1. 置信度 0-100 2. 至少 1 条原因 3. UI 区分高/中/低置信度 |
| P0-06 | **调解策略** | AI 输出 3-5 步调解策略，每步包含：步骤号、标题、具体描述、针对方、预期效果。 | 1. 至少 3 步 2. 每步有 target + expectedOutcome 3. 按顺序排列 |

## 5. 报告页面信息架构

### 设计原则

**结论先行，证据支撑，策略收尾。** 用户不应为了看到"谁更有理"而滚动三屏。

### 信息分层结构

```

│              第一屏：核心结论                  │  ← 不滚动可见
│  ┌───────────────────────────────────────┐  │
│  │  ⚖️ 仲裁结论                           │  │
```

### 各层级详细说明

#### 第一屏：核心结论（CoreVerdict）

| 元素 | 数据来源 | 交互 |
|------|---------|------|
| 双方分数对比 | `coreConclusion.scoreA / scoreB` | 无 |
| 胜方标记 | `coreConclusion.overallWinner` | 无 |
| 一句话结论 | `coreConclusion.oneLineVerdict` | 无 |
| 核心原因 (2-3条) | `coreConclusion.keyReasons` | 无 |
| 置信度进度条 | `coreConclusion.confidence` | hover 显示原因 |
| 建议行动 | `coreConclusion.recommendedAction` | 无 |

#### 第二屏：证据 & 情绪

| 元素 | 数据来源 | 交互 |
|------|---------|------|
| 关键证据列表 | `evidenceWeights[]` | 点击展开原文上下文 |
| 证据权重条 | `evidenceWeights[].weight` | 无 |
| 偏向标签 | `evidenceWeights[].favors` | 无 |
| 情绪曲线图 | `emotionCurve[]` | hover 显示触发原因 (P2) |

#### 第三屏：调解策略

| 元素 | 数据来源 | 交互 |
|------|---------|------|
| 步骤列表 | `mediationStrategy[]` | 点击展开详情 |
| 针对方标签 | `mediationStrategy[].target` | 无 |
| 难度标签 | `mediationStrategy[].difficulty` | 无 (P2) |

#### 第四屏：详细分析（折叠 Tab）

| Tab | 数据来源 | 默认状态 |
|-----|---------|---------|
| 人物画像 | `detailedAnalysis.characters` | 折叠 |
| 争议焦点 | `detailedAnalysis.conflicts` | 折叠 |

## 6. 新的 Analysis 数据结构

### 完整 TypeScript Schema

```typescript
// ═══════════════════════════════════════════════
// 核心结论（第一屏）
// ═══════════════════════════════════════════════

interface CoreConclusion {
  overallWinner: 'a' | 'b' | 'tie';
  scoreA: number;                  // 0-100, scoreA + scoreB = 100
  scoreB: number;
  oneLineVerdict: string;          // 一句话结论，如"甲方更有理，因为乙方在承诺上反复变卦"
  keyReasons: string[];            // 2-3 个核心原因
  recommendedAction: string;       // 建议的下一步行动
  confidence: number;              // 0-100, AI 判断置信度
  confidenceReasons: string[];     // 置信度高/低的原因
}

// ═══════════════════════════════════════════════
// 证据权重（第二屏）
// ═══════════════════════════════════════════════

interface EvidenceWeight {
  id: string;                      // "ev_w_1"
  speaker: string;                 // 说话人名字
  content: string;                 // 关键对话原文
  timestamp: string | null;        // 时间（如果有）
  weight: number;                  // 0-100, 证据权重
  weightReason: string;            // 为什么这条证据重要
  favors: 'a' | 'b' | 'neutral';  // 偏向哪一方
}

// ═══════════════════════════════════════════════
// 情绪曲线（第二屏）
// ═══════════════════════════════════════════════

interface EmotionPoint {
  timestamp: string | null;        // 时间
  emotion: string;                 // 情绪标签（生气/委屈/冷静/伤心等）
  intensity: number;               // 0-100, 情绪强度
  trigger: string;                 // 触发该情绪的原因
}

interface EmotionCurve {
  speaker: string;                 // 说话人名字
  points: EmotionPoint[];          // 情绪变化数据点序列
}

// ═══════════════════════════════════════════════
// 调解策略（第三屏）
// ═══════════════════════════════════════════════

interface MediationStep {
  step: number;                    // 步骤序号 1, 2, 3...
  title: string;                   // 步骤标题，如"冷处理24小时"
  description: string;             // 具体做什么
  target: 'a' | 'b' | 'both';     // 针对哪一方
  expectedOutcome: string;         // 预期效果
  difficulty: 'easy' | 'medium' | 'hard';  // 执行难度
}

// ═══════════════════════════════════════════════
// 详细分析（第四屏，折叠）
// ═══════════════════════════════════════════════

interface Character {
  name: string;
  role: 'party_a' | 'party_b' | 'other';
  personality: string;             // 性格特点
  stance: string;                  // 核心立场和诉求
  emotionalState: string;          // 整体情绪状态
  communicationStyle: string;      // 沟通风格（新增）
}

interface Conflict {
  topic: string;                   // 争议话题
  partyAStance: string;            // 甲方立场
  partyBStance: string;            // 乙方立场
  aiJudgment: string;              // AI 判断
  winner: 'a' | 'b' | 'tie';       // 该争议点谁更有理
  severity: 'low' | 'medium' | 'high';  // 严重程度（新增）
}

interface TimelineEvent {
  timestamp: string;
  speaker: string;
  content: string;                 // 关键对话内容摘要
  emotion: string;                 // 情绪标签
  significance: string;            // 为什么重要
  isTurningPoint: boolean;         // 是否为转折点（新增）
}

interface DetailedAnalysis {
  summary: string;                 // 案情摘要
  relationship: string;            // 人物关系
  characters: Character[];
  conflicts: Conflict[];
  timeline: TimelineEvent[];
}

// 建议（追问上下文用）
// ═══════════════════════════════════════════════

  toA: string[];
  toB: string[];
  toBoth: string[];
}

// ═══════════════════════════════════════════════
// 完整 Analysis 结构
// ═══════════════════════════════════════════════

interface Analysis {
  id: string;
  caseId: string;
  createdAt: string;

  // 第一层：核心结论（第一屏前置）
  coreConclusion: CoreConclusion;

  // 第二层：证据 & 情绪
  evidenceWeights: EvidenceWeight[];    // 3-8 条
  emotionCurve: EmotionCurve[];         // 每方一个

  // 第三层：调解策略
  mediationStrategy: MediationStep[];   // 3-5 步

  // 第四层：详细分析（折叠）
  detailedAnalysis: DetailedAnalysis;

  // 追问/建议
  advice: Advice;
}
```

## 7. Prompt 工程方案

### 当前 Prompt 问题

```
当前：你是一位经验丰富的情感调解专家和仲裁员。你的任务是基于提供的聊天记录，进行客观、深入的分析。
问题：①角色太泛 ②没有思维链引导 ③直接要一个大 JSON ④没有分层优先级 ⑤缺少证据溯源要求
```

### 新 Prompt 设计（CoT 思维链）

```
你是一位专业的对话争议分析师。你的专长是从聊天记录中提取关键证据、分析情绪动态、给出客观判断和可操作的调解方案。

## 分析流程（请严格按照以下步骤思考）

### 第一步：理解对话
- 通读全部聊天记录
- 识别对话双方（及第三方）
- 理解人物关系和对话背景
- 把握对话的整体走向

### 第二步：提取关键证据
- 找出 3-8 条对判断结果有决定性影响的关键对话
- 为每条证据评估权重（0-100）
- 判断该证据偏向哪一方
- 说明为什么这条证据重要

### 第三步：追踪情绪变化
- 为每一方建立情绪变化轨迹
- 标注每个情绪转折点的触发原因
- 评估情绪强度（0-100）
- 识别冲突升级的关键节点

### 第四步：综合判断
- 基于证据权重和情绪分析，给出综合评分
- scoreA + scoreB = 100，分数高的一方更有理
- 评估你的判断置信度（0-100）
- 说明置信度高或低的原因

### 第五步：制定调解策略
- 设计 3-5 步调解方案
- 每步要有具体的操作描述
- 标注针对哪一方和预期效果
- 评估执行难度

## 输出要求

请严格按照以下 JSON 格式输出（不要包含任何其他文字）：

{coreConclusion, evidenceWeights, emotionCurve, mediationStrategy, detailedAnalysis, advice}

## 评分规则

- scoreA + scoreB = 100
- 基于客观事实判断，不要被情绪化语言左右
- 证据权重 ≥80 的为"决定性证据"，60-79 为"重要证据"，<60 为"辅助证据"
- 置信度 ≥75 为"高置信"，50-74 为"中置信"，<50 为"低置信"
- 聊天记录可能不完整，在置信度中体现这一不确定性

请用中文输出所有内容。
```

### Prompt 关键改进点

| 改进点 | 当前 | 新方案 |
|--------|------|--------|
| 角色 | "调解专家"（泛） | "对话争议分析师"（具体） |
| 思维链 | 无，直接输出 JSON | 5 步引导：理解→证据→情绪→判断→策略 |
| 输出结构 | 6 个平铺字段 | 5 层递进 + advice |
| 证据溯源 | 无 | 每条证据标注 weight + favors + reason |
| 置信度 | 无 | confidence + confidenceReasons |
| 调解策略 | 只有 advice（笼统建议） | mediationStrategy（分步+目标+预期+难度） |
